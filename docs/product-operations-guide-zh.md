# Sealos 产品运营手册

> 适用对象：产品运营、客户成功、客服与售前
>
> 文档口径：以当前已上线版本为准
>
> 更新日期：2026 年 7 月 16 日

## 这是什么产品

Sealos 是面向开发者和团队的云操作系统。用户可以在一个项目里部署应用、创建数据库、配置公网访问，并查看服务状态、日志、指标和部署进度。

它适合 Web 应用、AI 应用、内部工具和数据服务等场景。用户不需要先搭建一套完整的基础设施，也不需要在多个控制台之间反复切换。从代码或镜像到服务上线，再到后续排查和调整，都可以在项目工作区内完成。

运营介绍产品时，可以用一句话概括：

> Sealos 把应用部署、数据库和日常运行管理放进同一个项目工作区，让团队更快地把服务跑起来，也更容易看懂它现在运行得怎么样。

## 谁会用 Sealos

Sealos 的主要用户是需要部署和维护在线服务的开发者或团队。常见需求包括：

- 从 GitHub 仓库部署一个新项目。
- 用现成的 Docker 镜像启动服务。
- 创建 PostgreSQL、MySQL、MongoDB 或 Redis 数据库。
- 从应用模板快速启动一套完整服务。
- 为应用配置公网地址或自定义域名。
- 查看应用和数据库的运行状态，处理部署失败、资源不足或连接异常。
- 在不接触底层集群配置的情况下调整副本、资源、环境变量和存储。

这份手册讲的是产品使用和运营口径，不是平台管理员的安装、升级或故障处置手册。集群安装、服务部署和平台级故障处理请使用部署文档与故障诊断 SOP。

## 先认识几个概念

### 项目

项目（Project）是用户组织资源和部署结果的工作区。一个项目可以包含多个应用、数据库和公网访问入口。

项目列表支持按名称或描述搜索，也可以置顶常用项目。项目名称和描述可以修改，描述最多 256 个字符。

删除项目是高风险操作。用户需要输入项目名称确认，项目所拥有的应用、数据库和模板资源可能同时被清理。执行前应先确认数据是否已经备份，以及项目内是否还有其他人在使用资源。

### 项目画布

项目画布（Project Canvas）可以理解为项目的资源地图。画布会展示应用、数据库、公网访问入口和部署中的任务，并根据实际配置显示资源之间的关系。

连接线不是用户手动画出来的备注。例如，一个应用通过环境变量引用了项目内数据库的连接信息，画布会据此显示应用和数据库之间的关系。

项目画布用于登录后的工作区管理，目前不支持生成匿名访问或公开分享链接。

### 应用

产品和部分界面中会使用 AP 表示应用。对用户沟通时直接说“应用”即可。

应用是实际运行代码的服务。它通常包含镜像、启动命令、环境变量、配置文件、资源额度、存储、监听端口和副本策略等配置。

### 数据库服务

数据库服务（DB Service）是项目内的托管数据库实例。当前产品创建流程支持 PostgreSQL、MySQL、MongoDB 和 Redis。

一个数据库服务里可能包含多个逻辑数据库、Schema、表、集合或 Key。产品里的“数据库连接”指应用或外部工具连接数据库；“数据库访问”指在 Sealos 内浏览数据对象，两者不是同一件事。

### 部署任务

无论用户从 GitHub、Docker 镜像、数据库还是模板开始部署，系统都会创建一条部署任务（Deployment Task）。部署任务记录当前进度、等待用户补充的内容、生成的资源以及失败原因。

部署任务不是聊天记录。即使部署由项目助手发起，部署状态仍以部署时间线为准。

## 创建项目的四种方式

从项目列表点击“新建项目（New Project）”后，用户可以选择四种创建方式。

### 从 GitHub 部署

适合已经有代码仓库，希望由平台完成构建和部署的用户。

用户可以输入仓库地址，也可以先授权 GitHub，再搜索并选择自己有权访问的公开或私有仓库。GitHub 授权绑定到当前 Sealos 用户，不是整个工作区共享。多人在同一个工作区协作时，每个人都需要使用自己的 GitHub 身份完成授权。

部署开始后，系统会分析仓库、准备构建和运行配置，并把进度写入部署时间线。某些项目可能需要用户补充环境变量、密钥或其他配置，任务会停在“等待输入”状态，提交内容后继续执行。

### 从 Docker 镜像部署

适合已有可运行镜像，或者希望明确控制运行参数的用户。

用户可以填写镜像地址、启动命令、参数、环境变量、配置文件、持久化目录和监听端口，也可以为监听端口生成公网地址。Docker 部署使用结构化配置执行，不应对外描述为“所有部署都由 AI 自动完成”。

### 创建数据库

适合先准备数据服务，再接入应用的场景。

当前可以选择 PostgreSQL、MySQL、MongoDB 或 Redis，并设置规格和副本数。数据库创建完成后会出现在项目画布中，用户可以复制连接信息，或把数据库连接引用添加到项目内应用的环境变量中。

### 从模板部署

适合希望快速启动一套现成应用的用户。

用户选择模板、填写模板要求的参数后即可开始部署。一个模板可能同时创建应用、数据库和存储等多种资源，最终结果会统一显示在项目画布中。

## 如何跟进一次部署

部署开始后，项目画布会先显示部署中的占位节点，部署任务提醒也会保留在画布上。点击任务即可打开部署时间线。

时间线里重点看三件事：

1. 当前进行到哪一步，例如准备、生成资源、应用配置或检查服务是否就绪。
2. 是否正在等待用户输入。补充完所需内容后，任务会继续执行。
3. 哪一步失败，以及页面给出的失败摘要和详细信息。处理工单时，建议让用户同时提供任务编号、失败步骤和可复制的错误详情。

部署任务常见状态如下：

| 状态 | 运营解释 |
| --- | --- |
| 排队中 | 任务已经创建，等待执行。 |
| 运行中 | 系统正在分析或准备部署。 |
| 等待输入 | 缺少配置，等待用户补充后继续。 |
| 应用中 | 资源正在写入平台并等待就绪。 |
| 已完成 | 部署流程已经完成。 |
| 失败 | 某一步未完成，需要查看失败原因。 |
| 已取消 | 用户停止了部署流程。 |

### 取消部署

运行中的任务可以取消。取消的含义是停止后续流程，不是自动回滚。

如果取消前已经创建了部分资源，这些资源可能继续保留在画布中。用户需要根据画布里的实际资源决定是否保留或手动删除，不能承诺“取消后环境一定恢复到部署前”。

### 重新部署

失败或已取消的任务可以重新部署。用户既可以沿用原配置，也可以编辑后重新部署。重新部署会创建一条新任务，不会改写原任务的历史。

如果上一次部署已经留下资源，新任务可能继续使用原来的资源标识，以便在同一批资源上收敛。重新部署前应提醒用户：部署期间做过的手工修改可能被新配置覆盖。

终态部署任务当前自动保留 30 天，产品没有提供逐条手动删除任务记录的功能。

## 在项目画布里做日常运营

### 查看应用状态

点击应用节点后，可以根据当前资源和平台支持情况进入设置、事件、版本历史、指标、日志和终端，也可以执行启动、停止、重启或删除。

停止或重启会造成服务中断。删除应用可能同时删除它拥有的持久化存储，数据可能无法恢复。涉及生产服务时，应先确认流量、备份和恢复方案。

### 调整应用配置

应用设置主要包括：

- 固定副本或按 CPU、内存自动扩缩容。
- CPU 和内存额度。
- 镜像与版本。
- 启动命令和参数。
- 配置文件与持久化存储。
- 环境变量和数据库连接引用。
- 监听端口、平台公网地址和自定义域名。

持久化存储通常只允许扩容，不允许缩容。部分存储挂载配置在创建后不能直接修改，遇到界面不允许提交时，不要引导用户反复重试，应先确认产品限制。

设置页面会保存当前编辑草稿。如果同一资源在用户编辑期间被其他人修改，系统会在提交时提示配置发生变化，让用户保留当前编辑或重新加载最新配置。已经提交但尚未同步完成的设置状态保存在当前浏览器中，因此换浏览器或换设备时不一定能看到同样的“应用中”提示。

### 查看日志和指标

应用和数据库都可以按资源支持情况查看日志。日志支持选择时间范围、容器、返回条数和文本搜索，默认从最近 60 分钟开始查看。

应用指标主要包括 CPU 和内存，数据库还可以查看存储。历史趋势最长为 24 小时。日志或指标显示不可用时，可能是资源尚未运行、当前用户权限不足，或平台的日志与监控服务暂时不可用。

日志窗口分为实时查看和固定时间段查看。排查已经发生的问题时，应固定时间范围，避免新日志不断进入后改变上下文。

### 使用终端

终端用于直接进入应用容器或数据库客户端，适合有相应技术能力和权限的用户。终端不是只读工具，执行的命令可能修改文件、配置或数据库内容。

客服和运营不要让用户把密码、Token 或完整连接串粘贴到工单、群聊或项目助手中。需要远程协助时，应优先收集脱敏后的错误信息。

### 查看版本和回滚

应用可以查看镜像版本记录，并在后端版本能力可用时回滚。较新的版本记录可以恢复更完整的应用配置，旧记录可能只能回滚镜像。对外不要承诺所有历史版本都能完整还原全部设置。

## 管理公网访问和自定义域名

应用监听端口默认用于项目或集群内部访问。用户可以为端口创建平台公网地址，也可以把自己的域名绑定到该地址。

绑定自定义域名时，用户需要在域名服务商处添加 CNAME 记录，指向页面给出的平台地址。提交时系统会检查 CNAME。当前版本不会持续轮询 DNS，因此用户后续修改了解析记录，页面可能要到再次编辑或提交时才发现变化。

公网地址状态反映的是域名、证书和平台路由是否准备好，不是应用业务接口的健康检查。应用返回 HTTP 404 或 500 时，地址仍可能显示为可访问。遇到“地址可访问但页面报错”的反馈，应继续查看应用日志和应用本身的响应。

自定义域名的重复校验范围当前是同一个命名空间。不要承诺平台已经完成全局域名占用检查。

## 数据库的日常运营

### 连接与公网访问

数据库节点会展示内网连接和公网连接。项目内应用优先使用内网连接；只有确实需要从平台外部访问时，才建议打开公网连接。

停止数据库会保留数据和配置，但会关闭公网访问，并暂停自动备份计划。再次启动后，系统会恢复原有备份设置。停止数据库不等于删除数据库。

### 数据库访问

数据库访问页面支持浏览逻辑数据库、Schema、表、视图、集合、索引和 Key，查看字段及分页数据，并按 CSV 或 NDJSON 导出。

当前产品开放的是受控只读能力，不支持在该页面执行任意 SQL、修改或删除数据、导入文件或创建表。单页最多返回 500 行，单次导出最多 100,000 行，超过部分会被截断。

只读限制只适用于数据库访问页面。数据库终端连接到可写主节点，具备相应权限的用户仍可能通过终端修改数据。

### 手动备份和自动备份

运行中的数据库可以创建手动备份。备份说明最多 120 个字符，执行中的备份不能删除。

每个数据库可以设置一套自动备份策略，支持每小时、每天或每周执行。计划使用 UTC 时间，保留期可以选择 1、3、7、14 或 30 天。关闭自动备份只会停止未来任务，不会删除已经生成的备份。

### 恢复数据库

恢复备份不会覆盖原数据库，也不是把原库原地回滚。系统会在同一个项目和命名空间中创建一个新的数据库服务，并继承源库的引擎、版本、规格、副本、存储和备份策略。

新库准备完成并完成数据核对后，用户需要自行决定是否切换应用连接，以及何时删除旧库。

## 项目助手

项目助手可以结合当前项目和当前选中的资源回答问题、解释状态、打开相应页面，并通过工具发起部署或其他受支持的操作。用户切换画布选中项后，后续消息会带上发送当时的资源上下文。

助手会话列表默认按当前用户分开显示，但这是一种产品视图，不是严格的保密边界。同一个工作区成员本身可能拥有读取命名空间资源的权限，因此不得宣传“聊天内容只有本人能看到”，也不要鼓励用户在对话中提交密钥或其他敏感信息。

如果平台配置了免费模型，界面会显示剩余免费对话次数。免费次数用完后，后续对话会自动切换到用户自己的 AI Proxy 计费，并在切换时提示一次。如果环境没有配置平台免费模型，助手可能从第一次对话开始就使用用户计费，界面也不会长期显示“付费中”标记。运营不能承诺助手始终免费。

## 常见问题与处理建议

### 部署一直停在等待输入

打开部署时间线，查看当前步骤要求的字段。敏感字段不会从上一次部署自动带回，重新部署时可能需要再次填写。

### 用户取消了部署，为什么画布里还有资源

取消只停止流程，不自动删除已经创建的资源。以画布显示的实际资源为准，需要清理时逐个确认后删除。

### 公网地址显示正常，但访问页面报错

公网地址状态只说明域名、证书和平台路由已经准备好。继续检查应用状态、监听端口、启动命令和应用日志。

### 自定义域名以前可用，现在解析不对

当前版本不会持续检查 DNS 漂移。让用户确认 CNAME 是否仍指向页面给出的平台地址，必要时重新进入设置并提交验证。

### 数据库恢复后为什么多了一个数据库

这是正常行为。恢复会创建新数据库，避免直接覆盖源库。核对新库数据后，再调整应用连接和旧库保留策略。

### 为什么同事部署 GitHub 项目时还要重新授权

GitHub OAuth 连接属于当前用户，不是工作区共享凭据。每位协作者都需要用自己的 GitHub 身份授权。

### 为什么设置提交后一直显示应用中

资源配置已经提交，但实际状态还没有与目标配置一致。可以刷新资源状态并查看事件；如果提示“配置在其他位置被修改”，应重新加载最新配置后再决定是否继续编辑。

### 日志、指标或终端入口不可用

先确认资源正在运行、数据库类型受支持、当前用户有权限。如果多个资源同时不可用，应转交平台运维检查日志、监控或终端服务。

### 可以把项目画布发给外部客户查看吗

不可以。当前没有公开项目预览或分享链接。外部演示应通过受控账号、屏幕共享或另行准备的产品材料完成。

## 运营话术禁区

下面这些说法与当前产品能力不符，不应出现在介绍、帮助文档或客户答复中。

| 不要这样说 | 建议说法 |
| --- | --- |
| 所有部署都由 AI 自动完成。 | GitHub 和自然语言部署会使用 AI 能力，Docker、数据库和模板按结构化配置执行。 |
| 取消部署会自动回滚。 | 取消会停止后续流程，已经创建的资源可能保留。 |
| 数据库恢复会把原库回滚到备份时间。 | 恢复会根据备份创建一个新数据库，原库不变。 |
| 数据库管理页面可以直接改数据或执行 SQL。 | 当前数据库访问页面支持只读浏览和导出；终端是另一项高权限能力。 |
| 项目可以生成公开分享链接。 | 项目画布只面向登录后的工作区管理。 |
| GitHub 授权一次，全团队都能用。 | GitHub 授权按 Sealos 用户绑定，每位用户独立授权。 |
| 项目助手聊天完全私密。 | 会话列表默认按用户分开，但不能把它当作严格保密边界。 |
| 项目助手永久免费。 | 有免费额度时优先使用免费次数，之后可能转为用户计费。 |
| 公网地址正常就代表应用业务正常。 | 地址状态表示平台路由就绪，业务响应仍需结合应用日志判断。 |
| 删除应用或项目随时都能恢复。 | 删除可能清理持久化数据，执行前必须确认备份和影响范围。 |

## 演示建议

一次完整产品演示可以控制在 10 到 15 分钟，按下面的顺序进行：

1. 在项目列表说明项目是应用、数据库和访问入口的统一工作区。
2. 选择 GitHub、Docker、数据库或模板中的一种方式创建项目。
3. 打开部署时间线，说明进度、等待输入、失败详情和重新部署。
4. 进入项目画布，展示应用、数据库、公网地址和资源关系。
5. 打开一个应用的设置、日志和指标，再展示数据库的只读访问与备份页面。
6. 用一个真实域名或预先准备的截图说明 CNAME 绑定过程。
7. 最后演示项目助手如何根据当前项目或选中资源回答问题。

演示环境应提前准备好 GitHub 授权、可用镜像或模板、平台路由域名，以及足够的 CPU、内存、存储和公网端口配额。不要在现场使用生产数据库做删除、恢复或终端写入演示。
