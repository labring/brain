# Snapshot Glass: Replace the Live Backdrop-Filter Sheet with a Pre-Blurred Texture

Chromium keeps no cache for `backdrop-filter`: it re-reads the framebuffer and re-blurs inside every produced frame whose damage overlaps the sheet, even when the change is painted *above* the glass, and no platform switch decouples this. The canvas glass sheet therefore pre-blurs its backdrop into two textures mounted as children of the masked sheet (`canvas-glass-snapshot.ts`), split by how they move: a screen-space **ambient plane** (surface color + bloom) counter-transformed against the viewport every frame, so the glow keeps flowing through the windows during a pan exactly like live sampling, and a flow-space transparent **content plane** (dot grid + edges) riding the viewport transform natively above it. Panning regenerates nothing; regens are event-driven (node geometry and edges throttled during drags, zoom settle, container resize, theme). Until both textures are painted — and on any browser that fails the support gate or whose color resolution fails — the live backdrop-filter keeps rendering unchanged.

## Equivalence tripwires

The bar is a per-window channel-mean delta ≤ 0.5/255 against live glass (pixelmatch alone is anti-aliasing-tolerant and waves through a +10/255 veil). Four choices are load-bearing at that scale: changing any of them will look correct in review and only show up in channel means. After touching the capture pipeline run `bun run e2e:glass` from `apps/registry` against the committed `glass-equivalence` fixture — there is no CI test pipeline today, so that spec is the guard.

- **float16 canvas contexts** (`GLASS_CONTEXT_SETTINGS`): an unorm8 texture quantizes the slowly-varying backdrop into a locally constant ≈0.5–0.8/255 flat veil. float16 leaves final-composite quantization as the only rounding, same as live.
- **Blend in gamma sRGB, not display-p3**: Blink rasterizes page tiles in gamma sRGB, so that is where the alpha blend and stroke antialiasing happen; a display-p3 canvas blends in gamma P3 and measures a flat ≈1/255 red bias. `colorSpace: "srgb"` + float16 is *extended* sRGB, so wide-gamut values survive as out-of-range floats instead of clamping.
- **Pre-flatten the bloom over the background** (`bloomGradientStops`): the CSS gradient's OKLab ramp is sampled densely, each sample converted and alpha-blended over the surface color numerically, then emitted as opaque stops. The ambient texture must never alpha-composite the bloom itself, and the background fill must use the same numeric source so the gradient edge stays seamless.
- **Match Blink's tiny-dot rasterization** (`drawDotsLayer`): Blink fills the xyflow pattern's r=1-device-px dot at full pixel coverage; canvas `arc()` true-AA gives ~0.6 coverage, an ≈0.3/255 energy deficit after the blur. Dots draw as squares while radius × scale ≤ 2 device px, and the grid phase keeps xyflow's operator-precedence quirk (`dotGridPhase`).
- Also load-bearing: the blur radius is read from `--canvas-glass-blur-radius` on the sheet, so a themed override moves both pipelines, and edge strokes are redrawn from the live `d` attributes and computed styles.

## The blurred-twin constraint

The two-plane split is the seam for a future ambient canvas background animation — the ambient plane is already the first blurred twin, "animated" by the per-frame viewport counter-transform. A new animated layer joins the same way: pre-blur it once, then run the *same* timeline on the blurred copy inside the glass while the sharp original animates below the sheet, which works because Gaussian blur commutes with translation exactly and with small scale/opacity changes approximately. That imposes a hard design constraint on code this record does not touch: **any future canvas-background animation must be transform/opacity-only.** Content mutation — hue rotation, gradient shifts, morphing, particles, video — invalidates the pre-blurred copy every frame and reintroduces the per-frame tax that is the whole economy of this decision. Low-frequency regenerate-on-change and short-lived exceptions that fall back to live blur are fine; continuous per-frame content mutation in a standing background is not.
