# Express Workbench Orchestration as Pure Transitions

Project Canvas orchestration used to be split across two modules where one was the sole caller of the other: `useProjectCanvas` exposed 17 options (8 callbacks) in and 30+ fields out, and `useProjectCanvasModule` repackaged that result field-by-field. The seam was shallow (deleting the inner module would only move its implementation into its single caller), and the ordering behavior between the coordinated pieces — Project Surfaces, selection/route sync, Settings Launch Context, leave guards, the Deployment Task Dock and Timeline, viewport directives — had no stable interface to be tested through. AIM-117 absorbed the inner hook and deleted it as an interface; the workbench is now one deep module: three identifiers in (`kubeconfig`, `namespace`, `projectId`, plus an optional clock seam), three semantic groups out (`actions`, `canvas`, `surfaces`). Its orchestration decisions live in `workbench-orchestration.ts` as pure transitions, `(state, event) → (nextState, effectPlan)`, extending the command-plan direction of ADR 0035. Session-local orchestration state lives in a hand-rolled subscription store (the repo's existing store shape) and changes only by committing transition results. The React hook is the effect boundary: it reads route snapshots, resource facts, and clock inputs, submits events, and executes effect plans (route writes, persistence, expiry scheduling, revalidation). Seven scenario families at the workbench interface — driven browser-free through an in-memory router adapter and a manual clock (`workbench-clock.ts`) — protect the behavior.

## Considered Options

- A method-rich mutable `WorkbenchController` class: rejected — mutation behind methods is not inspectable the way transition results are, and a controller invites becoming a second source of truth next to URL state, Project Runtime facts, and Canvas Layout. Explicitly prohibited by the AIM-117 ruling.
- A state library (zustand or similar) or any new general-purpose store: rejected — a third state idiom beside the existing hand-rolled subscription stores and nuqs route state; the ruling pinned the core to existing forms.
- Moving the external seam up into the React host component: rejected — the host's responsibilities (viewport insets, assistant intent bridge, edit-redeploy bridge, rendering) are host concerns, not orchestration.
- Direct unit tests for the inlined glue (dock notice timer state machine, deployment timeline auto-opener, manually-closed task set, stack-order wiring, covered→revalidate coupling): rejected — that glue's behavior exists only as interface scenarios; convenience unit tests would recreate the shallow test landscape the refactor removed.

## Consequences

- `useProjectCanvas` is gone. The workbench interface is the test surface: tests drive it through its public interface and assert observable outcomes only (render model contents, the URL update stream, directive/interaction store snapshots, dialog presence, stubbed fetch calls). A test that breaks when the implementation moves is testing past the interface.
- Session-local orchestration state — completion-notice expiries, the dock-dismissals mirror, the manually-closed timeline set, the viewport focus request sequence, stack-order overrides, and the covered-canvas edge memory — lives in `createWorkbenchOrchestrationStore` and changes only by committing transition results. It resets with the namespace/project identity semantics and dies with the unmounted workbench.
- New orchestration behavior lands as an event, a transition case, effect kinds, and an interface scenario — not as another `useEffect` with its own `useState`. The effect executor in the hook is the only place effects run.
- The only timer-driven orchestration behavior (dock notice expiry) is scheduled through the clock seam via `rescheduleNoticeExpiry` effects, so tests advance a manual clock instead of sleeping.
- Explicit internal seams keep their own modules and focused tests: route sync (single route-sync subscriber and Back/history semantics per ADR 0014/0035), the Settings Launch Context store, the viewport directive store, command plans, and render-model builders. Project Runtime observation and Canvas Layout persistence remain independent modules instantiated privately by the workbench (ADR 0029); rendering hosts and shared canvas primitives stay outside (ADR 0020).
